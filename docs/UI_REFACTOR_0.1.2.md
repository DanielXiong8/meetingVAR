# meetingVAR 0.1.2 UI 整理

基线：`origin/feat/desktop-ui`，提交 `a9abea5`。修改位于本地 `codex/ui-hierarchy` 分支。

## 代码修改方案与实现

| 文件 | 实现 |
| --- | --- |
| `desktop/web/index.html` | 项目资料、全库理解、确认词表分区；说明入口统一为标题旁 `(i)`；路径输入与读取按钮组成 Input Group；设置按运行环境、音频识别、自动保存、API、项目模型分组。 |
| `desktop/web/style.css` | 原生 CSS，无需 npm 或 Tailwind 构建。标题 16px/700、正文 14px、辅助信息 12px/#6B7280；行高 1.5；按钮与输入高度 40px；操作组 flex gap 12px；间距使用 4px 网格。 |
| `desktop/web/app.js` | 统一 `showNotice` 渲染状态和持久错误，`badge` 渲染数量；Tooltip 支持悬浮、聚焦、点击、Escape 与视口避让；理解任务集中管理按钮状态，重试保持全量/5 块参数；系统日志从字幕区移至折叠日志。 |
| `desktop/preview_ui.py`、`desktop/preview/mock.js` | 标准库 HTTP 服务注入合成 Python 桥，用于 macOS/Windows 普通浏览器联调，不导入真实后端。原生桌面入口不会加载 mock。 |

按钮优先级：开始全库理解、写入词表、保存设置为品牌蓝实心；预算、文件夹选择等为线框；小样、测试、打开目录为幽灵按钮。项目索引、原始词表、预算明细、人物和事件摘录默认折叠。

“先算预算”仍是理解任务的前置步骤。预算通过后才能启动；运行中禁止换项目及重复启动。取消请求发出后继续等后端终态，不提前宣称任务停止。错误横幅的重试分别调用预算、读取、理解、凭证检测等原操作；没有增加桥接口。

只对本地模型显示后端提供的本地耗时估算，自定义 API 不再套用本地耗时，也不展示未验证的“快 10~50 倍”。模型来源标签旁的说明保留项目内容发送位置；实际 API 的账单和延迟由所选厂商决定。

## macOS 本地 UI 预览

在仓库根运行：

```bash
python3 desktop/preview_ui.py --port 8765
```

浏览器访问 `http://127.0.0.1:8765`。顶部明确标为合成数据，可切换正常、理解中断、模型未就绪、读取失败场景。中断场景首次任务失败，重试成功；可分别用全量和小样验证参数。用 Ctrl+C 关闭服务器。

该预览不读取真实配置和项目、不调用云 API、不使用麦克风或录屏设备。模拟的开始、保存和凭证检测只用于检查界面，不能证明实际引擎可用。

## Windows 验收与交付

最终目标仍为 Windows pywebview/WebView2；本次未更改采集、讯飞、引擎子进程、文件选择、媒体服务和打包接口。CSS 使用本地字体栈，优先 Segoe UI/微软雅黑，macOS 用 PingFang SC 回退；不依赖外部字体/CDN。

协作者在 Windows UI 环境中运行 `python desktop/app.py`，检查原生文件夹对话框、中文/空格/长路径、WebView2 键盘提示、窗口最小尺寸与 125%/150% 系统缩放。真实 RTASR、兴趣 API、录屏和会议收尾需要 Windows 设备与实际服务单独验收；浏览器合成检查不能替代。

确认后按 `desktop/README.md` 重新构建 UI exe 和 setup；现有构建脚本含作者机器路径，需要使用对应的 Windows 打包环境。改前端源文件不会自动更新已安装的 exe。


## 第二轮：色彩与互动体验

本轮采用办公产品常见的蓝白体系：大面积浅色阅读面，蓝色用于导航和主要操作，紫色少量标识项目理解；绿色表示成功、橙色提醒、红色错误，均同时保留文字和图标。设计依据是 [Fluent 色彩角色](https://fluent2.microsoft.design/color) 和 [Fluent 功能性动效](https://fluent2.microsoft.design/motion)，未引入 Fluent 组件库。配色偏好仍有个体差异，这些规范不能证明所有用户都喜欢某种颜色。

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| 主色 | `#2563EB` / 悬停 `#1D4ED8` | 主要按钮、选中导航、焦点 |
| 辅助色 | `#6D28D9` / 浅底 `#F5F3FF` | 项目理解标记、当前阅读步骤 |
| 阅读背景 | `#F5F7FC` / 卡片 `#FFFFFF` | 大面积中性阅读面 |
| 辅助文字 | `#6B7280` | 路径、说明、明细；彩色底采用足够浅的色阶 |

关键文本对比度（按 sRGB 相对亮度公式核算）：主按钮白字 5.17:1，蓝色文字/白底 6.70:1，辅助文字/页面底 4.51:1，辅助文字/白卡片 4.83:1，紫色文字/浅紫底 6.48:1。未据此声称已经完成整个应用的无障碍认证。

新增交互：

- 四步流程导航随真实 UI 结果更新，点击只定位与聚焦对应控件，不自动启动收费任务；未满足前置条件的步骤禁用。
- 理解任务显示实际加载状态与进度，按钮同步提示“计算中/理解中”；未编造进度百分比。
- 词表支持全选/清空，实时显示选中数。清空后禁止写入；更改选择后撤销当前选择的“已确认”步骤标记。
- 文件树目录支持键盘 Enter/空格展开与收起。
- 160ms 的按钮/卡片交互反馈、短页面淡入、Tooltip 过渡、成功反馈；录制键有悬停和按下反馈。Input Group 的按钮保持无位移，避免按下时露出缝隙。
- 尊重 `prefers-reduced-motion`，关闭动画和过渡；为 Windows 高对比度模式保留系统颜色与轮廓。

新增合成检查：流程导航实际聚焦主操作；清空为 0/4 并禁用写入，全选后单独取消可得 3/4，写入后四步完成；修改选择重新进入确认步骤。900×600 下四步与操作组均保持同一行，无横向溢出；模拟减少动态效果后过渡为 `0s`、页面动画为 `none`。这些仍是 macOS 浏览器检查，Windows WebView2、系统缩放与高对比度模式需实机验收。


本轮补充检查：彩色词条样例可见叶子文本的计算对比度均不低于 4.5:1；选中词条的辅助字使用更浅的蓝底以保持 `#6B7280` 可读性。模型未就绪时阅读步骤禁用；理解中断时确认步骤保持禁用，重试仍进入原来的 5 块小样。小样结束明确显示“小样试跑完成”，不把部分阅读覆盖率描述成整库已读完。新主题截图和交互预览均使用合成数据，未调用真实服务。
