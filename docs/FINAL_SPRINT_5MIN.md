# 最后冲刺：5 分钟现场 Demo + PPT

> 目标不是“功能最多”，而是让评委在 5 分钟内记住一句话：
>
> **别人帮你记下来，meetingVAR 帮你证出来。**

## 1. 已确认的前提

- 形式：**5 分钟现场 Demo + PPT**。
- 硬件：Magic Bay 情况未知；官方指南说明模块端走 USB2.0/3.0，摄像头/小屏都在生态范围内。先按“标准 UVC 摄像头 + 任意 Windows 副屏 HUD”实现，拿到主机侧 SDK 再加适配；不赌真机，不逆向。
- 网络：不限制；但主 Demo 建议走本地链路，云端只做显式增强。
- 团队：你负责核心/整合/路演；两位队友主要做 UI 优化和少量边缘工作。

## 2. 五个方向，各只留一个抓手

| 方向 | 唯一抓手 | 5 分钟里怎么出现 | 不做什么 |
|---|---|---|---|
| 差异性 | “证据 Agent”不是“会议纪要” | 开场 20 秒 + 收尾一句话 | 不讲通用任务/日程/数字分身 |
| 取证性 | 可校验证据包 | 现场生成 ZIP，打开 manifest，跑 SHA256 | 不宣称“法律级/司法采信” |
| 联想硬件 | Magic Bay 副屏 = 证据 HUD | 把 HUD 拖到第二屏，显示录制/承诺/证据数 | 不伪造真机集成 |
| 数据安全 | 本地链路可离线 | 状态栏 `local` 标识 + 断网 fallback | 主流程不依赖 Agnes |
| UI | 三屏 + 一个 HUD | 聊天、证据包、承诺账本 | 不展示 100 节点毛线球 |

## 4. 5 分钟逐秒脚本

### 0:00–0:25 钩子

**PPT 第 1 页：一张很顺的 AI 纪要，和高亮的一句“漏掉的话”。**

口播：

> “这是一份很顺的 AI 纪要。但它漏掉了最重要的一句：‘那篇论文可能影响你的课题。’  
> 你回看时，纪要没有；全量录屏两小时，你找不到。  
> 我们做的不是更好的纪要，是**会议证据**。”

### 0:25–1:20 现场采集（60 秒）

**屏幕：meetingVAR 首页 → 开始会议 → 实时字幕 + 屏幕预览。**

提前安排 teammate 说三句话（不要即兴）：

1. “第一版周五交，小王负责。”
2. “预算先按三十万算。”
3. “这个风险会影响下周三的联调。”

操作：

- 点「开始会议」；
- 让说话人说 45–60 秒；
- 点「结束会议」。

**注意**：现场只演示“采集 + 命中”，不要在现场等完整后处理。承诺账本用预置数据。

### 1:20–2:15 承诺账本（预置两场会议）

**屏幕：聊天 → 「承诺账本」。**

口播：

> “这是我们过去两周的项目记忆。普通纪要只会写‘交付时间调整’，我们能看到：谁先承诺、谁改了口、哪一场、原话是什么。”

画面：

- 旧承诺：周五交付 / 小王；
- 新承诺：下周三 / 小李；
- diff：`due: 周五 → 下周三`、`owner: 小王 → 小李`；
- 点“原句”跳到对应会议时间戳。

### 2:15–3:05 证据包（现场生成）

**屏幕：聊天 → 「生成证据包」→ 确认 → 证据包查看页。**

口播：

> “现在把刚才那 60 秒变成一份可以带走的证据包：音频、屏幕帧、转写、manifest、每个文件的 SHA256。”

操作：

1. 输入“把刚才命中的片段生成证据包”；
2. 点确认；
3. 打开证据包查看页；
4. 点“校验”——全部通过；
5. 展示 `manifest.json` 里的 session/clip/时间窗/来源设备。

**这是全场最重要的 50 秒**：评委能看到一个真实文件，而不是一段回答。

### 3:05–3:50 找回 30 秒

**屏幕：聊天 → 「找回 30 秒」→ 输入“预算三十万那段”。**

画面：

- 返回 1–3 个片段卡；
- 每张卡：时间、说话人、原句、匹配原因、屏幕帧；
- 点播放，直接跳到该片段；
- 说明：这是本地 RAG + 时间戳，不是模型编的。

### 3:50–4:35 Magic Bay / HUD

**屏幕：把 HUD 窗口拖到第二块屏（没有 Magic Bay 就用普通外接屏/平板扩展）。**

口播：

> “开会时你不需要一直盯着主屏。Magic Bay 这块副屏就是证据 HUD：录制状态、最近一句、当前承诺、证据数量。  
> 我们按标准 Windows 显示接口做，不依赖私有协议；拿到联想 SDK 再加一层适配。”

画面：

- HUD 显示 `REC 00:47`、`本地`、最近一句、`承诺 1`、`证据 2`；
- 拔掉副屏，HUD 自动回主屏（可选，30 秒内完成）。

### 4:35–5:00 收尾

**PPT 最后一页：三列对比 + 一句话。**

| 普通 AI 纪要 | 全量录屏 | meetingVAR |
|---|---|---|
| 一段摘要 | 两小时视频 | 可回放证据 + 项目记忆 |
| 原话弱 | 找不动 | 秒级定位 |
| 不可校验 | 文件大 | SHA256 证据包 |
| 云端为主 | 隐私风险 | 本地优先 |

口播：

> “别人帮你记下来，meetingVAR 帮你证出来。  
> 我们不是另一个会议纪要 App，我们是 AI PC 上的个人证据层。”

## 5. PPT 结构（6 页，够用）

1. **封面**：meetingVAR — AI PC 的个人证据 Agent。
2. **痛点**：AI 纪要很顺，但漏掉最重要的 1%；全量录屏找不到；平台回放没有。
3. **方案**：选择性取证 + 证据包 + 承诺账本 + 秒级定位（一张流程图）。
4. **现场 Demo**：只放一张“证据包查看页”截图，其余现场操作。
5. **为什么是联想 AI PC**：本地 ASR/索引/证据；Magic Bay 副屏 HUD；数据不出机。
6. **收尾**：三列对比 + “别人帮你记下来，我们帮你证出来”。

不要在 PPT 里放：模型参数、17 队对比、100 节点图谱、完整架构图（放 backup）。

```json
// ledger row
{"title": "...", "owner": "...", "due": "...", "status": "active", "changes": [{"field": "due", "from": "周五", "to": "下周三"}], "evidence": [...]}

// moment segment
{"session_id": "...", "start": 123.4, "end": 156.7, "text": "...", "clip_id": "...", "score": 0.82, "why": ["预算"]}
```

## 7. 冲刺顺序（按 5 天算，按实际截止日压缩）

### Day 1：冻结 + 数据

- 冻结三屏和 5 分钟脚本；

- 确认“周五 → 下周三”的账本能出来；
- UI 同学拿到 mock JSON。

### Day 2：证据包查看页

- 后端加 `evidence_pack_info` / `verify_evidence_pack` API；
- 前端证据包页 + 校验按钮；
- 目标：现场点 3 下能看到“全部通过”。

### Day 3：账本 + 片段卡 + HUD

- 账本表格/diff；
- Find Moment 片段卡；
- HUD 第二屏（任意显示器）；
- 目标：三屏都能走通。

### Day 4：联调 + fallback

- 在线/断网、单屏/双屏、无麦克风；
- 录 5 分钟 fallback；
- PPT 定稿；
- 目标：连续 3 次完整走通。

### Day 5：排练 + 打包

- 按 5 分钟计时排练 5 遍；
- 删除讲不清的功能；
- 安装包/版本号/桌面快捷方式；
- 目标：现场只点 6 次以内。

## 8. Demo 数据设计

### 预置会议 A（旧承诺）

- 场景：项目周会；
- 关键句：“第一版周五交，小王负责。”
- 产出：commitment fact，due=周五，owner=小王。

### 预置会议 B（改口）

- 场景：联调会；
- 关键句：“周五来不及，改到下周三，小李来盯。”
- 产出：同一 canonical key 的新版本，due=下周三，owner=小李；
- 账本显示 diff。

### 现场会议 C（证据包）

- 场景：60 秒站会；
- 关键句：预算三十万 + 风险影响联调；
- 产出：一个命中 clip，用于现场生成证据包；
- 不依赖现场后处理出账本。

> 如果现场采集没有触发 clip，证据包会空。Day 1 必须验证“说这几句话一定命中”；不行就改成手动 VAR 标记。

## 9. Fallback 方案

1. **首选**：现场 60 秒采集 + 预置账本。
2. **二选一**：如果 ASR/麦克风失败，直接播放预录的 60 秒会议音频（系统环回），走同一管线。
3. **兜底**：播放 5 分钟完整录屏；口播继续，不现场操作。
4. **网络**：不依赖云端；如果必须用 Agnes，提前缓存结果，不在现场等。
5. **设备**：自带笔记本 + 麦克风 + 第二块屏（或平板扩展）；不假设主办方设备。

## 11. 还需要确认的问题

1. **截止日期**是哪天？上面按 5 天排；如果只有 72 小时，需要砍掉 HUD 和 Find Moment 卡片。
2. 有没有 **Lenovo ThinkBook 16p Gen 6 / Magic Bay 测试机**？没有就按普通第二屏演示，不宣称真机。
3. 现场是否允许**安装未签名软件 / 管理员权限**？是否必须用主办方电脑？
4. 评委构成是技术、商业还是联想业务？如果偏商业，PPT 多讲场景/收费；偏技术，多讲证据链/本地架构。
5. 能否使用**队友出镜录音**？如果不能，全部用预录/虚构数据。
6. 是否接受“**可校验完整性**”而不是“法律级取证”的表述？建议接受，避免过度承诺。
7. 是否同意**主 Demo 不用云端**？网络不限制，但安全方向需要一个本地故事。
8. PPT 是否有模板/页数/品牌规范？没有就按 6 页 16:9 做。
