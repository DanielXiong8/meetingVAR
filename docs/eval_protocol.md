# 验证协议（Evaluation Protocol v1）

> 依 ChatGPT 交叉评审（2026-10-08）制定。三层验收 + 反泄漏纪律。
> 数据来源分离纪律：**构建词表所用材料与评测剧本/标注必须物理隔离**——
> 仿真项目（spikes/b1_rag/sample_project）的组会纪要含演示剧本蓝本，
> 正式评测禁用其作为记忆源。

## A 层 · 触发判断（决赛前目标）

- **对象**：三层监听（L1/L2/L3）的命中判断
- **真值**：双标注者独立标注"应取证事件"（start/end + 描述），分歧协商定标
- **指标**：事件级 Precision / Recall / F1 / 每小时误触发数（原始 TP/FP/FN 计数必须保留）
- **事件定义**：预测事件 = 相邻命中合并（gap ≤ 90s）；匹配 = 时间重叠或中心偏差 ≤ 45s，一对一贪心
- **工具**：`src/meetingvar/eval/matching.py`（CLI: `python -m meetingvar.eval.matching --pool <dir> --labels <json> --hours <时长>`）
- **对照**：
  - A1 剧本 vs 开放讨论（测剧本乐观偏差）
  - A2 已见术语 vs 未见表达（同义改写/代词/否定句/无热词的重要信息，单独报告）
  - A3 干净 vs 噪声（重叠说话/远场/背景音）
- **纪律**：冻结词表/阈值/代码版本后跑测试集；不许看结果调参后再测同一集

## C 层 · 用户效用（赛后首项）

**模式对照实验**（直接验证产品主张）：
- 模式 A：全量记录 + 事后检索
- 模式 B：meetingVAR 选择性保存 + 检索
- 同一组目标事实、相同时间限制，比较：事实找回率 / 每事实检索耗时 / 审阅无关材料量 / 因未保存而无法核验的事实数

## 反泄漏纪律（每次评测前检查）

1. 词表/画像构建材料 ∌ 评测剧本内容
2. 评测集与开发集按整场划分（相邻片段不同组）
3. 阈值/模型/代码版本冻结记录在案（git SHA + config 快照）
4. 报告分项指标（按会议条件），不只报总体 F1
