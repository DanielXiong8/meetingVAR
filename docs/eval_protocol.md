> v1 依 ChatGPT 交叉评审（2026-10-08）制定；v1.1 经 2026-10-10 独立验收轮修订：
> 补齐零落盘边界（G1a/G1b/G1c）、回溯缓冲与 HD 补录的分层测试、匹配器边界与数据校验、

## 0 · 术语与时间轴定义（实现严格对应）

| 名称 | 定义 | 出现位置 |
|---|---|---|
| 绝对时间戳 | 单调时钟秒（live=墙钟；replay=模拟基点+偏移） | Session 内部（ring / trigger_ts） |
| 会议相对秒 | 绝对时间戳 − 会话起点，`max(0, ·)` 截断 | pool JSON：`ts`、`audio.*_ts`、screens manifest |
| 环形缓冲格 | **固定 1 秒**（16bit 16kHz = 32000 字节），容量 `RING_SECONDS`=600 格 | `pipeline._ring` |
| 回溯窗 | `[trigger − LOOKBACK, trigger]`，LOOKBACK 默认 300s，env `MEETINGVAR_LOOKBACK` | `pipeline._make_clip` |
| 片段音频物理窗口 | 窗内**已到达**的整格 + 不足 1s 的尾块（格对齐） | `data/clips/<clip_id>/<clip_id>.wav` |

**不变量**：① 格时间戳间隔 1.0s ⇔ 格内音频 32000 字节（不再是"0.5s 音频配 1.0s 标签"）；
② `RING_SECONDS ≥ LOOKBACK_SECONDS`（默认 600 ≥ 300，违反则该断言失败）；
③ 片段只含触发前已到达的数据，不含任何"未来"音频。

`audio.start_ts/end_ts` 是**片段内转写句的跨度**（事件时间锚点），不是 wav 物理起止；
命中但回溯窗内无转写时取 `0.0/0.0`（评测按 0 点事件处理）。

## A 层 · 触发判断（决赛前目标，需剧本音频）

- **对象**：三层监听（L1/L2/L3）的命中判断
- **真值**：双标注者独立标注"应取证事件"（start/end + 描述），分歧协商定标
- **指标**：事件级 Precision / Recall / F1 / 每小时误触发数（原始 TP/FP/FN 计数必须保留）
- **资源指标**（2026-10-11 GPT 裁决新增，用于比较策略而非预设"正常范围"）：
  每小时片段数 / 每小时实际保存音频秒数 / 保存音频时长÷会议时长 / 片段间回溯窗重叠比例 /
  每小时误触发数。参考量级：B-raw 428 片段/3.8h ≈ 每 32s 一次回看（35.7h 片段音频/3.8h 会议 = 9.4×）。
- **事件定义与匹配规则**（`src/meetingvar/eval/matching.py`，2026-10-10 加固后）：
  - 预测事件 = 相邻命中片段按 `merge_gap`（默认 90s）合并，**输入乱序不影响结果**（内部排序）；
  - 匹配 = 时间重叠 > 0 **或** 中心偏差 ≤ `tol`（默认 45s，evaluate 已正确透传）；
  - 贪心一对一：按重叠降序归属（等值按索引，确定性）；一个真值最多一个预测，反之亦然；
  - 非法输入显式报错：负时间戳 / start > end / 真值缺字段 / `meeting_hours ≤ 0` → `ValueError`；
  - P/R/F1 分母为 0 时约定取 0.0（不虚报 1.0）。
  - **`merge_gap=90s` 与 `tol=45s` 是设计参数，不是真实数据校准出的最优值**：
    两个真实事件间隔 < 90s 且各有一个预测时会被并入同一预测事件（丢一个 TP）——
    正式评测必须同时报告这两个参数的敏感性。
- **工具**：`python -m meetingvar.eval.matching --pool <dir> --labels <json> --hours <时长>`
- **对照**：A1 剧本 vs 开放讨论；A2 已见术语 vs 未见表达（同义改写/代词/否定句/无热词的重要信息）；A3 干净 vs 噪声
- **纪律**：冻结词表/阈值/代码版本后跑测试集；不许看结果调参后再测同一集
- **状态**：⏳ 待剧本音频（人工 #4）。**当前没有任何真实 P/R 数值，不得对外引用**。

## A2 层 · 纠错质量（2026-10-11 新增，GPT 裁决定案）

**指标定义**（对"实际发生的改写"逐条人工核验，听原始音频判定真实词形）：

$$\text{Correction Precision}=\frac{\text{正确改写数}}{\text{全部实际改写数}}$$

$$\text{Correction Recall}=\frac{\text{正确改写的可纠正错误数}}{\text{真值中可纠正错误总数}}$$

**谨慎表述三条（GPT 警示，报告措辞必须遵守）**：
1. A 组（人工 8 词）16 处纠错全检 ≠ "纠错准确率高"——只能表述为"人工精选词表展示了有效纠错案例"；
2. B-raw 的 7457 处纠错 ≠ 7457 个独立错误（同词多次改写），493 行变化 ≠ 493 行全部错误——
   行差异率是**改动范围**指标，不能替代纠错精度；
3. 对照组零片段只证明该次运行未命中，零持久化的一般性证明由 G1a/G1b/G1c 审计承担。

**双轨验证线**：
- **轨道一（优先）：真实会议纠错评测**——从真实会议抽 ~100 个纠错候选实例（覆盖英文/中文/
  专业术语/常见词误改/改写链），标注者**听原始音频**判定实际说出的词形（不能只看对照组文本，
  对照组 ASR 本身也可能错）；每例标注：音频支持的正确词形 / 原始 ASR 是否错误 / 纠错是否正确 /
  是否误改；高危样本第二人复核。
- **轨道二（并行/稍后）：TTS 受控测试**——已知文本注入近音错，测守卫能否拒绝不合理替换
  （重点覆盖 This→think、used→user 类常见词互换）；结果单独报告，不得混入真实会议准确率。
- CER/WER（改写前后）只作总体改善参考，不能取代逐条核验。

**词表分层与改写守卫（2026-10-11 GPT 裁决 v1，已实现）**：
`memory/govern.py` 四状态（approved/correction/watch/excluded）+ 词形守卫 + 常用词表；
`correct()` 三状态 records（accepted/review_required + reason）：中文等长近音才自动改写、
拉丁 ratio≥0.75 且原词非常用才自动改写，其余保留原文进待审队列；撤销=恢复原文片段
（不得反向再跑纠错器）。B-governed 实验设计见 decision_log 2026-10-11（续）。

## B 层 · 证据保全（本层为"应用层持久化与缓冲语义"验收）

### B1 · 零落盘三级承诺（`tests/audit_zero_persistence.py` 真模型 + `tests/test_persistence_policy.py` 替身）

| 级别 | 场景 | 判定标准 | 实测 |
|---|---|---|---|
| G1a | 纯静音、零转写、零命中 | 产物目录零新增（**文件与目录**）+ 仓库工作树零变更 | ✅ |
| G1b | 正常语音、**成功转写**、零命中 | 同上；summary 报出内存转写句数但 `transcript_json is None` | ✅（真模型 7 句转写零落盘） |
| G1c | 有命中 | 新增仅限策略内产物，数量可枚举：`pool/<sid>/{transcript.json, summary.json, <clip>.json}` + `clips/<clip>/<clip>.wav`（有截屏再有 screens/；digest 后另有 `reports/<sid>/{minutes.md, var_reports.md}`） | ✅ |

策略解释（**文档明确，非遗漏**）：命中会话会把**全场转写文本**落盘（薄纪要"全场概要"的原料）；
重证据（音频/屏幕）仍只存命中窗。未命中会话连目录都不留——"没事故就什么都不落盘"。

**审计范围声明（重要）**：以上测试是**应用层持久化写入审计**——覆盖被测进程显式写入的
产物目录与仓库工作树；**不覆盖**：OS 临时目录（ASR 转写用临时 wav，正常路径 `finally` 删除）、
注册表、页面文件、崩溃转储、其他进程行为。**不得据此宣称"操作系统级绝对零写盘"**；
需要该级别结论须上 Procmon 等系统级监控。

写盘点静态清点（全部路径，grep 可复核）：

| 路径 | 触发条件 | 说明 |
|---|---|---|
| `data/pool/<sid>/{transcript.json,summary.json,<clip>.json}` | 仅命中（G1c） | 会话产物 |
| `data/clips/<clip>/{<clip>.wav, screens/*.jpg, manifest.txt}` | 仅命中 | 片段媒体 |
| `data/hd/hd_*/{f_*.rgb, meta.json, hd_clip.mp4}` | 仅命中且 `--hd` | 高清补录 |
| `data/reports/<sid>/{minutes.md, var_reports.md}` | 仅命中且 digest | 纪要 |
| `data/terms.txt`、`data/persons.json` | 词表层（`terms --memory`） | 项目记忆派生，非会议内容 |
| `<项目>/meetingvar/minutes/*` | 仅命中且 `go` 归档 | 跨会话热词演化 |
| 系统临时目录 `*.wav` | 每次 ASR 调用 | 转写载体，`finally` 删除；崩溃时可能残留 |

### B2 · 回溯缓冲语义（`tests/test_ring_lookback.py`，确定性替身 30 组合）

- 覆盖：格时间戳/音频长度一致性；触发窗口上下界；连续性（无重复/缺口/越界）；容量与淘汰；
  早期触发（缓冲未满）；`trigger≈LOOKBACK` 边界（299/300/301）；保留上限边界（599/600/601）；
  长时运行（900s）；非整秒触发（305.5）；块长 0.5s / 5s / 3.7s（含残块）。
- 修复前实证缺陷：格为 0.5s 音频却标 1.0s（时间戳 2× 膨胀）→ replay 形状（5s 块）片段
  **在触发点前最多丢 2.5s 音频**（多个触发点全复现失败）；容量实际 3000s ≠ 文档 600s。
- 修复后：全部 30 组合通过；900s 长跑后缓冲恰为 600 格、旧数据正确淘汰、片段恰为最近 300s。

### B3 · HD 高清补录（`tests/test_hd_lifecycle.py`，可控屏幕替身 + ffprobe）

**资源约束（用户拍板 2026-10-10）**：帧双线性缩到 `HD_WIDTH=1280` 宽后落盘；
**每场（=进程）临时帧总预算 5GiB，跨多次命中共享，逐帧硬上限（不超预算一个字节）**；
目标帧率 = 剩余预算/帧尺寸/补录时长（标称 30fps 只是上限）；预算放不下 1 帧时跳过并提示。

- 覆盖：启动条件（仅命中）、启动延迟、录满自动停、`stop()` 立即停、重复命中不重复启动、
  录满后再命中新目录、mss 缺失静默降级、**mp4 可解码且时长≈真实录制时长**、帧序列清理、
  `meta.json`（尺寸/帧数/计划帧率/实测帧率/预算用量/是否触发上限）落档；
  **缩放尺寸**（2560×1600→1280×800，窄屏不放大）、**预算折算帧率**（20 帧/4s→5fps 仍覆盖 4s）、
  **跨命中累计降帧**（第 2 轮 5fps < 第 1 轮 10fps）、**用尽跳过不留空目录**、**硬上限恰好截断**、
  **命中→HD→片段池 hd_clip_dir 接线**（11 例）。
- 修复前实证缺陷：帧以 raw RGB 写入 `*.png` → ffmpeg 实际解码失败，但代码不检查返回码，
  **谎报"合成完成"并删除帧序列（唯一的证据副本）**；mp4 为 0 字节/moov atom missing。
- 修复后：rawvideo 输入 + 返回码校验 + 失败保留帧；实测帧率合成（抓屏跟不上标称帧率时
  视频时长仍与真实时长一致）。
- **真实屏幕实测（本机 2560×1600，5s 缩样）**：缩放后 1280×800（帧 3.07MB，原 12.3MB）；
  达成 13.2fps（瓶颈 = mss 抓屏 ~51ms + 缩放 ~25ms，**30fps 标称在本机不可达**）；
  90s 帧量由硬上限保证 ≤5GiB；**mp4 实测 ≈0.019MB/s → 90s 静态桌面 ≈1.7MB**（MB 级）。
- **未验证（边界明确）**：真实显示器 90s 端到端长跑（掉帧曲线/长时稳定性）；动态内容
  （视频、翻页）下 mp4 体积上界未实测——1.7MB/90s 是最低端估计。

## 短句过滤策略（2026-10-10 固化，`tests/test_short_sentence_filter.py`）

单点过滤在 `pipeline._flush`（`len(text.strip()) < config.MIN_TEXT_CHARS`，默认 2），
因此同时决定三件事：① 是否进入转写 ② 是否参与触发 ③ 是否进证据与纪要。

| 语义类别 | 例 | 进入转写/触发/证据 |
|---|---|---|
| 单字确认 | 是 / 好 | ❌（默认阈值下丢弃） |
| 单字指令 | 停 | ❌（**已知代价**：有效单字应答也丢） |
| 双字否定 | 不是 / 别改 | ✅ |
| 双字指令 | 重测 | ✅（可触发） |
| 噪声碎片 | 嗯 / 空串 | ❌ |
| 正常长句 | 会后请确认… | ✅ |

阈值可逆：`MEETINGVAR_MIN_TEXT_CHARS=1` 可保留单字句（噪声一并进来）。
**边界**：单字热词在默认配置下不可能触发——若某项目需要以单字为热词，先调阈值再评测。

## 残余风险（2026-10-10 登记，含未验证项）

1. **live 采集 100ms 丢帧窗口**：主循环 `last_ts = time.time()` 取在读取之后，快照与赋值之间
   落入的捕获块不会被下一轮取走（≤100ms 单次、偶发）——需真实会议长跑观测，本阶段未改（避免动高频路径）。
2. **HD 资源**：临时空间已按用户决策封顶（5GiB/场，预算折算帧率+逐帧硬上限，实测不超）；
   标称 30fps 在本机不可达（实测 13.2fps@1280×800）——**帧率是尽力值，不是承诺**，
   meta.json 如实记录实测值；动态内容下的 mp4 体积上界未实测。
3. **异常退出**：kill -9 时 HD 帧+meta 保留可再合成；pool/clips 已写文件为准；无崩溃演练。
4. **真实设备/实时性**：live 路径（WASAPI 环回、2fps 截屏缓冲）本轮未做端到端长跑。


## D 层 · 事件重要性判定（L3 裁判，2026-10-13 v0 冻结稿）

> 依 GPT 裁决建立。区分两类判断：**话题在场（topicality）≠ 事件重要（significance）**。
> 当前 L1 只测前者，本层定义后者的识别、输出与验收标准。
> **Phase 0 只冻结定义与基准；Phase 1 起离线实验；测试通过前不改真实保存链路（验收原则③）。**

### D1 · 事件框架（v0）

一级类型：`DECISION` 决策 / `COMMITMENT` 任务承诺 / `DIRECTION` 方向与边界 /
`RISK_BLOCKER` 风险与阻塞 / `OPEN_QUESTION` 未决问题 / `DISAGREEMENT` 重要分歧 /
`EVIDENCE_UPDATE` 关键证据变化。

独立字段：`event_status` ∈ {proposed, discussed, decided, assigned, rejected, deferred,
unresolved, revised}；`importance_reason`（自然语言）+ 五个可分维度（关注点相关性/
决策执行影响/新颖性与变化/后续影响/证据强度）——**第一阶段禁止输出单个 importance 数值**。

### D2 · L3 输出契约（触发必须可回溯到真实轮次）

```json
{
  "hit": true, "event_type": "COMMITMENT", "event_status": "assigned",
  "focus_id": "focus_2", "evidence_turn_ids": ["turn_481"],
  "evidence_quote": "这部分我周五前给出结果", "reason": "形成明确交付承诺",
  "confidence": 0.0, "owner": "speaker_2", "deadline": "周五", "related_event_id": null
}
```
字段规则：`confidence` 非校准概率（仅占位）；`owner/deadline` 允许为空；
`evidence_turn_ids` 必须指向原始转写（引用原句准确率进入验收指标）；
**不得以模型事后摘要替代原始证据**。

### D3 · 架构（v0，Phase 1 对照）

高召回候选信号（L1 话题锚点 + 对话行为规则：承诺/确认/否决/风险/责任分配句式）
+ **独立周期性滑窗 LLM 裁判**（不能只靠粗筛入口——否则整体召回被粗筛召回封顶）
+ 事件去重（按事件区间 + 事件身份）。起点参数：窗口 120s / 步长 30s /
P95 触发延迟 ≤90s（须 < 300s 回溯时限并留异常余量）；LLM 来不及不得无限排队——
合并过期窗口或拉大步长后重测召回与延迟。

### D4 · 指标与预算（主次分明）

| 指标 | 口径 | 地位 |
|---|---|---|
| 事件级召回 Recall = TP/(TP+FN) | 人工标注事件中被至少一次正确捕获（事件级去重） | **主指标**（漏报致命） |
| 事件级精确率 Precision = TP/(TP+FP) | 判为重要的事件符合留存标准的比例 | 次要 |
| 每小时误保存次数 | FP_persisted / 会议小时数 | 持久化成本，单独统计 |
| 每小时新增持久化时长 | 秒/小时 | 与隐私预算共同约束 |
| P50/P95 触发延迟、引用原句准确率、事件区间定位误差 | — | 工程验收 |

**"宁多存勿漏"的边界**：事件发现偏向召回，但持久化受证据门槛 + 隐私预算共同约束；
首轮预算假设 = 每小时误保存 1–2 次（**待验证假设，非标准**）；报告不同阈值下的召回-误保存曲线，
主看召回与 F2。

### D5 · 评估基准与对照实验

- **基准**：`test2_event_benchmark_v0`（test2 目录 benchmark_v0/；双标注者整场标注，
  负例必须人工核对；三条已知正例 ≠ 总体召回率）；标注 schema 见其 labels_skeleton.json；
- **对照（Phase 1，离线）**：B0 现热词基线（含触发泄漏回归：项目实体重复出现不得单独构成保存理由）/
  B1 无 LLM 对话规则 / B2 单窗口 LLM / B3 关注清单+滑窗 LLM（后续 B4 混合）；
- **数据纪律**：每次运行记录转写来源（原始 vs 纠错后）、纠错状态、窗口区间、模型版本、触发时间；
  开发集/测试集按**整场会议**划分，禁止相邻滑窗跨集；
- **两阶段证据**：test2 = 开发集/回归基准（Phase 1–2 用）；盲测（Phase 3）= 新增不同主题/语种会议。

### D6 · 验收三原则（GPT 裁决原文落地）

1. **词表纠错与事件触发解耦**：纠错被接受不得直接触发保存（L1 在纠错后文本上匹配须改为
   在原始转写上匹配，或经显式设计）；
2. **事件证据可回溯**：每次 L3 命中指向原始转写真实轮次与时间；
3. **测试未通过不改真实保存链路**：既有零落盘与资源生命周期测试继续有效，L3 新增
   离线→影子→触发三级验收，不得因引入语义模型放宽既有隐私边界。
