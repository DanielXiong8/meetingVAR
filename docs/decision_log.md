## 2026-10-10（续）· HD 补录产品决策落地：临时 5GB/场 + 最终产物 MB 级

**来源**：用户对验收报告中的 HD 资源风险（90s@1440p 约 33GB 临时帧）给出硬约束——
"顶多 5G 临时文件/每场，最后生成的厚薄纪要应该是 MB 级"，并选择推荐方案
（降到实测可达帧率 + 双线性缩到 1280 宽）。

### 落地内容（`src/meetingvar/capture/hd.py` + `config.py`）

| 项 | 实现 | 实测/验证 |
|---|---|---|
| 缩放 | 帧双线性缩到 `HD_WIDTH=1280` 宽（窄屏不放大；宽高取偶适配 yuv420p） | 2560×1600→1280×800：帧 3.07MB（原 12.3MB，↓4×） |
| 每场临时预算 | `HD_TEMP_BUDGET_BYTES=5GiB`（env `MEETINGVAR_HD_TEMP_GB`）；**同一 HDCapture 实例跨多次命中共享**（=一场会议） | 逐帧硬上限：累计 ≤ 预算（不超 1 字节） |
| 帧率编排 | 目标帧率 = 剩余预算/帧尺寸/补录时长，标称 30fps 仅为上限；触底 `FPS_FLOOR=1.0` 后由硬上限截断 | 20 帧/4s → 5fps 且仍覆盖 4s（时长不缩水）；第 2 次命中 5fps < 第 1 次 10fps |
| 预算用尽 | 放不下 1 帧 → 跳过补录（不留空目录）+ 提示；回溯音频+截屏照常 | 单测断言无新目录、`_skipped_for_budget` |
| 诚实标注 | `meta.json` 记录 fps_nominal/planned/actual、帧数、预算用量、budget_hit；完成语打印 mp4 MB 与累计用量 | HD 11 例全绿（含 ffprobe 与管线接线） |

**真实屏幕实测（本机 2560×1600，5s 缩样 + 5GiB 预算）**：缩放后 1280×800、达成 13.2fps
（瓶颈 = mss 抓屏 ~51ms + PIL 缩放 ~25ms），90s 帧量 ≤5GiB（构造保证）；
**mp4 ≈0.019MB/s → 90s 静态桌面 ≈1.7MB（MB 级 ✓）**。标称 30fps 在本机不可达——
帧率改为"尽力值"，实测值落 meta 并用于合成（视频时长始终 ≈ 真实时长）。

### 代价与残余（写明，不粉饰）

1. **分辨率**：1280 宽对 1440p 屏是 0.5× 降采样——UI 文字仍可读，但细节（小字号代码）
   损失需真实会议内容确认（产品取舍，用户已拍板）；
2. **帧率**：实测 13fps（本机），平滑度低于 30fps 叙事——路演/BP 中"30fps 补录"表述应改为
   "高帧率补录（实测可达 ~13–20fps，视机型）"；
3. 动态内容（视频/翻页）下 mp4 体积上界未实测（1.7MB/90s 是最低端估计）；真实 90s 长跑未做。

  （**未改，等用户确认后一并改 BP/PPT**，避免擅自改答辩材料）。
