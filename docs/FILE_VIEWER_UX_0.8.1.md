# 0.8.1 项目文件查看器体验修复

日期：2026-10-20

0.8.0 已经把 PDF、DOCX、PPTX、PPT/DOC、XML/TSV 和常见代码文件接入统一文本抽取，并提供了点击文件树打开查看器的能力。本版只修复真实安装版操作中暴露的三个体验问题，不改变抽取与安全边界。

## 修复

1. **项目抽屉先显示文件树**
   - 窗口为 1050×680 DIP 时，项目抽屉实际宽度约 782 CSS px，`project-grid` 进入单列模式。
   - 原有顺序是“项目材料 → 全库理解 → 项目文件”，用户点开项目后必须滚过整张材料卡才能看到文件。
   - 窄窗口下给 `.project-tree-card` 加 `order:-1`，文件树置顶；宽屏仍保持右侧文件树布局。

2. **扫描项目不再覆盖页标题**
   - `scanProject()` 结束时调用 `newChat()`，而 `newChat()` 无条件把 `pageTitle` 写回“新任务”，导致项目抽屉标题错乱。
   - 现在只有在没有打开管理抽屉时才重置标题与焦点；抽屉打开时保留“项目”标题，也不会把焦点送给被遮住的 Composer。

3. **刷新当前项目不再清空对话**
   - `scanProject()` 记录进入前的项目路径，只有项目确实变化时才 `newChat()`。
   - 点击文件树的刷新按钮只重扫文件，不重置当前会话。

  - 打开“项目”抽屉，文件树直接出现在首屏，834 份文档计数正常。
  - 点击图片文件，查看器显示 164.9 KB 图片与“用系统应用打开”。
  - 点击 DOCX，查看器显示带行号的提取文本，元信息为 `15.7 KB · office`。
  - 切换到 `D:\项目\联想未来办公AI创新挑战\meetingVAR` 后，文件树显示 README/计划/代码等 94 份文档。
- 完整测试：469 项通过，0 跳过；`compileall` 通过；CLI 仿真通过。
- 安装包与内置 EXE 的 SHA256 见 `docs/DEVELOPMENT_STATUS.md`。

## 已知边界

- 扩展名与内容不一致的文件按内容处理。例如一个实际是 ZIP 的 `.txt` 会显示“二进制文件”，这是正确行为。
- 扫描件/图片型 PDF 没有 OCR 文本时提示改用系统应用打开。
- 超过 15 MB 的图片/音视频不内嵌，超过 200,000 字符的文本截断显示。
- 旧版 `.ppt/.doc` 依赖本机 LibreOffice；未安装时提示无法提取。
