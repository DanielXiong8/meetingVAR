# 演示剧本 · 录制台词本 v1

> **录制目标**：一次会议同时拿到三样东西——①多说话人音频（C1 说话人分离的真实验证素材）②C3 平台实测（腾讯会议真实会议）③演示用剧本音频（PPT 现场回放用）。
> **人员**：3 人（师兄A、师兄B、PI；PI 最好与 A/B 性别不同，利于说话人分离）。
> **时长**：主线 8–10 分钟；辅线可分开另录或同期顺带。
> **录制方式（推荐）**：腾讯会议线上开，meetingVAR 端侧采系统声音；同时各自本地开录音备份。念稿自然一点，允许口头语。

## 监听词表（录制前喂给 meetingVAR / 用于命中设计）

`测序污染` `S3` `index hopping` `kraken2` `UMI` `论文` `Q30` `重测`

## 主线 · 组会（约 9 分钟）

**【0:00–1:00 开场｜PI】**
"人齐了，开始。今天三个汇报：先宏基因组的进展，再数据 QC，最后对一下下周安排。汇报的人控制节奏，别拖。"

**【1:00–3:00 师兄A 汇报 · 与"我"无关的内容（干扰项）｜师兄A】**
"我这周主要是宏基因组流程的升级。之前用 metaphlan 做物种注释，跑全量太慢，现在换成 kraken2 加 bracken，速度提升大概三倍，注释一致性也有改善。数据库我上周刚更新过，用的是标准库加自定义库。后面我打算把流程打包成 snakemake，谁要用直接找我。另外提一句，kraken2 的内存占用比较高，建议在服务器上跑，笔记本会很吃力。"

**【3:00–3:20 PI 对 A 的回应（表面无关，实际埋下文）｜PI】**
"可以。kraken2 这套数据库你整理好共享一下，说不定别的地方用得上。"

**【3:20–5:30 师兄B 汇报 · 部分相关（QC 数据，引出 S3）｜师兄B】**
"我讲一下上周那批混测的 QC 情况。六个样本里五个都正常，Q30 都在 93 以上，duplication 也不高，没什么问题。但是 S3 明显异常：Q30 只有 86，duplication 率干到 35%，而且物种分布里混进来大量大肠杆菌的 reads，这个量级不正常。我们初步怀疑是测序污染，两个可能：要么是 index hopping，要么是上机混样的时候出了问题。fastp 的 adapter trimming 我都跑过了，切完低质量尾巴 Q30 也就提升一两个点，说明不是数据质量本身的问题，是污染。"

**【5:30–6:10 PI 追问（关键铺垫段——命中关键词的"前文上下文"就在这里）｜PI】**
"S3 这个事要重视。如果确认是 index hopping，影响的不只是这一批，上机记录要整个重新核对，后面批次都有风险。这样，先查 index hopping，把 S3 和它同 lane 邻居样本的 index 序列对一遍；再用 kraken2 确认一下外源物种到底是什么。排查脚本本周跑完，结果周三给我。"

**【6:10–6:40 PI 点名（高潮：那句"对你有影响"）｜PI】**
"对了，还有个事。那篇 Nature Methods 上用 UMI 做去污染的方法，**对你有影响，你会后看一下**，重点看它的实验设计部分，评估一下适不适合我们的场景，下次组会说一下你的想法。"

**【6:40–7:30 师兄A 顺嘴聊开（干扰恢复）｜师兄A】**
"说到这个，我之前也遇到过污染，后来发现是实验室扩增那段气溶胶的问题，换了个操作间就好了。你们这个不一定是同一类原因，别急着下结论。"

**【7:30–8:30 收尾布置任务（行动项来源）｜PI】**
"总结一下：第一，S3 污染排查周三前出结果，index hopping 和 kraken2 两条线并行；第二，重测的事先放一放，等排查结论；第三，UMI 那篇论文的评估下周组会讲。散会。"

## 辅线一 · 项目例会（约 3 分钟，工程场景）

**【负责人】**："这周重点讲两件事：一是搜索服务的改造，二是埋点方案。搜索那边现在平均响应 800 毫秒，目标压到 300 以内，方案是加一层缓存加索引重建。埋点这边，产品要求转化率的口径统一，客户端和服务端各埋一层，事件名走枚举表，别再出现同一事件三个名字的情况。测试环境本周五之前部署完，下周一灰度。有问题现在提。"

## 辅线二 · 培训课（约 3 分钟，学习场景）

**【讲师】**："今天讲模型评估。第一个概念，过拟合：训练集上表现很好，测试集一塌糊涂，模型把噪声都背下来了。第二个概念，交叉验证：数据切成 K 份，轮流做验证集，取平均，这样评估更稳。记住一句话：**评估不是为了证明模型好，是为了在它上线前发现它哪里坏**。最后留个思考题：为什么交叉验证比单次划分更可靠？"
