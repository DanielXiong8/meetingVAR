# meetingVAR 项目总览（2026-10-05 · 面向所有人，无需背景）

> 一句话：**装在你自己电脑上的"会议取证器"**。平时它像一台开着但不写卡的行车记录仪；一旦会议里聊到你关心的东西（它从你的项目记忆里自己学来的），它就把"刚才那一会儿"的完整证据——声音和屏幕——保存下来。会后给你两份报告：一份全场流水账（**薄纪要**），一份只关于你的深度分析（**厚纪要/VAR 报告**）。

## 全链路数据流

```
 會前：你的项目文件夹 ──自动抽取──► 监听词表（术语+人名）+ 兴趣画像
            │（零手动输入，agent 自己读）
 会中：任意会议软件的声音 ──► 系统音频环回 ──► 16k单声道
            │                                    │
            │                    ┌───────────────┴──────────────┐
            │                    │ 草稿层（常驻内存，不落盘）        │
            │                    │  · 音频环形缓冲：最近 10 分钟     │
            │                    │  · 录屏环形缓冲：2fps 最近 120 秒  │
            │                    │  · 每 30s 增量转写（说话人+标点）  │
            │                    └───────────────┬──────────────┘
            │                                    ▼
            │            三层监听：L1 热词 / L2 兴趣相似度 / L3 回车手动
            │                                    │ 命中
            │                                    ▼
            │              转正：回溯 120s 音频 + 关键帧截屏 → 片段池
 会后：digest ──► 薄纪要（全场）+ 厚纪要 VAR 报告（每片段，带项目记忆深读）
            └── review ──► Clip.review + feedback.json（人工反馈 v1；自动权重更新待后续校准）
```

## 七个功能与实现原理（通俗版）

### 1. 听得见"系统里的声音"——平台无关
**做什么**：不管你用腾讯会议、飞书、微信视频还是网页播放器开会，它都能采到对方的声音，不用装任何插件。
**怎么实现**：Windows 声卡有一个"总混音台"——所有应用放出来的声音最后都要从这里出去（WASAPI 系统音频环回）。我们不在会议软件里做内嵌，而是在混音台上装了个"分线盒"（pyaudiowpatch 库）。这就是 README 里"系统级、平台无关"的技术底气。

### 2. 默认不保存，但永远"差一点就保存了"——环形缓冲
**做什么**：默认硬盘上什么都不写；命中时能拿到**命中前 2 分钟**的完整音频。
**怎么实现**：内存里一个首尾相接的队列，每秒一格，只保留最近 600 格（10 分钟），新的进来最老的自动被挤掉。通俗说就是行车记录仪的循环录像：一直在录，但没"事故"就什么都不落盘。"比全量纪要工具更隐私"这个卖点的技术根基就是这段代码。

### 3. 听得懂——本地识别四件套
**做什么**：每 30 秒把新音频变成"带说话人标签、带标点"的文字。
**怎么实现**：FunASR 框架下四个模型接力（全部固化在 D:\env\models，推理跑在你的 RTX 5060 上，无网络）：
- **fsmn-vad**：先把音频切成"有人在说话"的段，沉默部分跳过；
- **SenseVoiceSmall**：识别主体。它是"非自回归"模型——普通模型像打字机一个字一个字蹦，它像盖章机整句一次盖出来，所以快（18 秒音频 GPU 上不到 1 秒转完）；
- **CAM++**：给每句话算"声纹指纹"，指纹相近判为同一人，按句标 spk0/spk1；
- **punc_ct-transformer**：给无标点草稿补标点（不补的话厚纪要没法读）。

### 4. 听得准——术语纠错
**做什么**：自动修复"测序污染→测试污染"这类近音错写、"kraken2→crowken二"这类拼写漂移。
**怎么实现**：讯飞的热词是"解码时加权"（我们实测 funasr 里该参数无效，见 SETUP 坑 15），我们走"解码后纠错"：中文词用**首字拼音相同 + 尾字拼音相同 + 字形重合过半**三条件判定（"测试污染"和"测序污染"头 ce 同、尾 ran 同、字形重合 3/4，命中）；英文词去掉数字后比相似度（"crowken" vs "kraken" = 83%），连被听成汉字的数字尾巴（"二"→"2"）都会转回来。五用例全绿，含两个防误报用例。

### 5. 知道你关心什么——三层监听 + 自动记忆
**做什么**：判断会议里哪一刻"与你有关"。三层互为保险：
- **L1 热词**：词表匹配，同一个词 5 分钟内不重复触发（防止"测序污染"连说十遍触发十次）；
- **L2 兴趣相似度**：把你的项目文档变成 TF-IDF"关键词指纹库"，转写每 30 秒去按一次指纹，重合度超阈值（0.25）就触发——通俗说，项目文档就是你的"兴趣画像"；
- **L3 手动 VAR**：按一下回车，永远兜底（足球里主裁也有权主动看 VAR）。
**记忆从哪来**：F1 词表自动化——你只给一个项目文件夹路径，它自己读：markdown 标题/加粗/`词条：定义` 形态抽术语，jieba 词性标注认人名（PI、师兄A），拉丁词按频次收（kraken2）。**用户手动热词是覆盖项，不是必选项**。

### 6. 只保存重要的那一刻——命中转正
**做什么**：触发瞬间自动完成取证。
**怎么实现**：从环形缓冲抽出**前 120 秒**音频存成 wav（VAR 回看的是"已经发生的回合"——命中前的铺垫才是价值所在），同时从录屏缓冲（2fps JPEG，内存上限约 55MB）取出对应时间段的关键帧，连同触发原因（哪个词/几分/谁按的）打包成一个 Clip JSON，写进"待审片段池"（`data/pool/<会话>/<clip_id>.json`，字段契约见 docs/pool_schema.md）。

### 7. 会后两份报告——digest
**做什么**：一条命令出双报告。
**怎么实现**：
- **薄纪要**：全场速览 + 按 5 分钟分章 + 行动项候选（正则只抽带行动语义的**原句**，不编造）。配了 LLM 环境变量就出叙述版，没配就出结构化模板版并如实标注〔模板版〕；
- **厚纪要（VAR 报告）**：每个片段一份，prompt 自动带入命中原因 + 上下文逐字稿 + 项目记忆检索结果，并强制模型区分"录音里明确说的"与"〔推断〕"——对应比赛"必须说明哪些环节真实实现"的硬要求。

### 8. 不开会也能测——replay + CI
**做什么**：`meetingvar replay --wav 任意音频` 直接灌进整条管线；`digest` 出报告。
**怎么实现**：replay 用模拟时间轴驱动同一个 Session 类，live 与 replay 共享全部逻辑——这是测试和演示的兜底路径（现场翻车就放 replay）。另外仓库有 model-free CI（队友贡献）：每次 PR 自动跑不需要模型的契约测试，`pip install --no-deps` 规避 1GB 重依赖。

## 技术栈

Python 3.10 · FunASR（ASR/VAD/说话人/标点）· pyaudiowpatch（环回）· dxcam/mss（录屏）· scikit-learn + jieba（L2/词表）· pypinyin（纠错）· GitHub Actions（CI）。模型权重约 1.3GB 本地固化；运行内存：音频缓冲 ~19MB + 录屏缓冲 ≤55MB。

## 诚实边界（比赛要求"说明哪些真实实现"）

- **真实实现且已验证**：以上全部——replay 端到端绿、断网模拟绿（死代理强制断网）、纠错五用例绿、冒烟测试 4/4；
- **已知局限**：转写粒度 30s（讯飞是字级流式）；说话人重叠段分离弱；行动项正则会漏；数字规整未做（"q三十"）；live record 端到端静音待查（坑 20：默认环回=耳机零信号，需人工看一眼托盘）；
- **未做/规划**：厚纪要 LLM 输出（现为模板版）、评价后的自动阈值校准、命中后向前捕获、发音个性化；评价反馈的人工闭环 v1 已可通过 `review` 命令写回 `Clip.review` 并生成摘要。
