# 0.5.0：对话即产品（In-app Chat）

日期：2026-10-20。0.4.0 仍有“功能页 + 表单”的问题；0.5.0 把主页改成真正的会话线程，会议能力通过 Agent 工具在对话里调用。

## 1. 会话结构

```text
左侧栏：新建对话 / 搜索 / 技能 / 项目 / 会议库
        项目列表
        最近对话（按项目持久化）
        本机工作区
主区：空状态问候 + 快捷技能
      对话线程（用户/助手气泡、工具轨迹、引用）
      底部 Composer（项目、模型、只读 Agent、发送）
```

- 首页不再跳转 Agent 页；输入直接创建/继续对话。
- 用户消息右侧、助手消息左侧；助手消息带时间、步骤数、工具轨迹和引用。
- 工具轨迹可折叠，显示工具名与参数；引用显示 `session:turn_id` 或事实名。
- Composer 固定在底部；Enter 发送，Shift+Enter 换行。
- 侧栏“最近对话”来自当前项目；点击恢复历史线程。

## 2. 对话路由

`src/meetingvar/agent/chat.py`：

| 输入 | 处理 |
|---|---|
| 你好/谢谢/在吗 | 本地问候，不调用模型 |
| 含会议/项目/课堂/交付/承诺/原话/记作等关键词 | 有界 ReAct AgentLoop（工具 + 引用校验） |
| 其他普通问题 | 直接模型对话，不调用工具 |

- 会议问题会携带最近 10 轮对话历史，规划器和执行器都能看到上下文。
- 普通对话不检索会议，避免把闲聊变成无意义工具调用。
- 每次对话追加到 `<项目>/meetingvar/agent_memory/conversations/<id>.json`。

## 3. 会议工具（对话内可用）

- `search_sessions`：跨会话关键词检索
- `list_sessions`：最近会议
- `get_transcript_window`：读取原句
- `search_memory` / `read_fact`：项目事实
- `compare_sessions`：对比两场会议
- `get_session_overview`：会话概览
- `project_status`：项目进度、事实、会前关注、最近会议
- `plan_project_reading`：全库阅读预算（离线）

定义/规则类问题会先做确定性 RAG 预检索；若模型只查项目记忆就拒答，会在已有证据上强制再回答一次，避免“记忆为空 = 会议没说过”。

## 4. 快捷动作

- 开始会议：主页原地展开会议控制台并开始；不跳页。
- 会议纪要：发送“列出最近会议并总结决定/行动项/未决问题”。
- 项目进展：发送“查看项目进度、事实、会前关注”。
- 技能：在对话中显示技能面板（最近会议总结/项目进度/全库阅读预算/找原话/未决问题）。
- 新建对话：清空当前线程，创建新会话。

## 5. 持久化与边界

- 对话按项目保存；切换项目会开新对话。
- 会话消息最多保留 240 条；工具正文不写入对话，只保留工具名/参数和最终引用。
- 写操作（保存关注清单、写入会议事实）仍走原审批流程，不在普通聊天里自动写。
- 外部连接器/MCP、RBAC/多租户、硬沙箱仍未实现。
- 真实模型回答质量仍以引用校验为底线，不代表通用准确率。
