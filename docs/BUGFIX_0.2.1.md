# 0.2.1 Agent 桌面实测修复记录

日期：2026-10-19。测试对象：Windows 真实窗口；先在已安装 meetingVAR 0.2.0 上逐页操作，修复后安装 0.2.1 复测。当前项目 `D:\项目\联想未来办公AI创新挑战\meetingVAR`，本地 16K Qwen3-4B 服务。

## 发现并修复

### 1. 本地模型生成关注清单失败，界面没有原因

- 现象：Agent 页点“生成关注清单”，状态只显示“关注清单生成失败”，无错误码；项目已有 11 份文档。
- 复现：`FocusAgent(max_chars=12000)` 在本地 16K 上下文下返回失败；同一项目 `max_chars=4000` 成功（4 条关注点）。根因是提示材料超出本地上下文预算。
- 修复：`FocusAgent` 对 `context_budget/truncated/invalid_output` 自动缩短材料重试（12000→6000→4000→3000）；失败返回 `error_code`/`error`，界面显示具体原因。
- 验证：本地 16K 模型、12000 起始材料自动重试成功，生成 7 条关注点；新增2项回归。

### 2. 会后事实预览存在同类上下文/错误不可见问题

- 现象：`PostMeetingAgent.preview()` 只把异常类名写入错误，UI 无法区分上下文超限、输出非法或模型失败。
- 修复：新增 `PostMeetingError`；对上下文超限/截断/非法输出自动缩短转写分块；`error_code/error` 透传到 bridge/UI；写入失败也返回明确错误。
- 验证：新增2项回归（上下文重试、invalid_output）。

### 3. 会话下拉包含没有转写的场次

- 现象：Agent 页下拉列出所有 pool 会话；部分会话没有 `transcript.json`（中断/零转写），选中后只能得到“没有保存的转写”。
- 修复：`list_sessions` 增加 `has_transcript`；Agent 页只列出有转写的会话，占位文案改为“选择有转写的会话”。

### 4. 无依据问答状态误导

- 现象：项目记忆为 0 时问“最近有什么决定？”，回答是“未找到足够依据”，但状态写成“回答完成（未通过引用校验）”，让人误以为模型给了无引用答案。
- 修复：`answered=false` 时状态显示“项目记忆中没有足够依据”，不再追加“未通过引用校验”。

### 5. 操作后状态栏停留在“正在…”

- 现象：生成关注清单/预览事实/提问成功后，顶部状态仍显示“正在…”。
- 修复：各操作成功/失败后写入明确状态；加载/忙碌状态仍由按钮禁用控制。

### 6. 关注清单来源未保存到新版本

- 现象：重新生成并保存关注清单时，`sources` 可能被空数组覆盖。
- 修复：`agent_status` 返回 `focus_sources`；前端保留并随勾选项一起保存。

### 7. “测试生成”在本地模型下实际测试了自定义 API

- 现象：设置页厂商选“本地模型”、本地服务运行中，点“测试生成”，结果却显示“已通过实际JSON生成验证：deepseek-flash”；本机模型并未被调用，却被标记为验证通过。
- 根因：`Backend.test_llm()` 固定调用 `_test_provider("custom")`。
- 修复：`test_llm()` 使用当前 `llm_provider`；新增回归验证本地厂商传入本地地址/模型并返回 `provider=local`。
- 验证：真实窗口复测时从“deepseek-flash”改为 `meetingvar-local`；专项测试通过。
