# Test5 考试题驱动关注问题：首轮命中实验

日期：2026-10-21

## 方法

从 `2021–2025 高等微积分2 期末试卷/参考答案` 提取考点，写成 12 条关注问题（`benchmarks/meeting_evidence/test5_focus_questions.json`）。首轮不做全 68 小时，而是选 4 个代表性考点做最小闭环：

| Case | 关注问题 | 对应课堂 | 10 分钟抽样起点 |
|---|---|---|---|
| F2 | 复合函数链式法则 / 反函数、隐函数偏导 | 2026-03-20 | 6% |
| F4 | 二元极值 / 条件极值 / 拉格朗日 | 2026-04-10 | 6% |
| F6 | 第一型曲面积分 / 参数化 / 面积微元 | 2026-05-15 | 5% |
| F9 | 正项级数 / 幂级数 / 收敛半径 | 2026-06-05 | 5% |

每个 case：

1. 截取 600 秒 WAV；
2. 用对应关注问题作为项目记忆，跑 `meetingvar replay`；
3. 检查保存片段的 transcript 是否出现该考点的关键词；
4. 有至少一个相关片段 = hit；相关片段 / 总片段 = keyword precision。

注意：抽样点由“PDF 记录页位置 + 课堂主题映射”人工选定，**不是逐字时间戳真值**；这轮验证的是“关注问题能否把片段带到正确主题”，不是秒级定位精度。

## 首轮结果

| Case | 片段数 | 关键词相关 | Keyword precision | Hit |
|---|---:|---:|---:|---|
| F2 链式法则 | 2 | 2 | 100% | YES |
| F4 极值/拉格朗日 | 1 | 1 | 100% | YES |
| F6 第一型曲面积分 | 6 | 4 | 67% | YES |
| F9 级数/收敛 | 2 | 2 | 100% | YES |
| **合计** | **11** | **9** | **81.8%** | **4/4** |

- 4/4 关注问题都至少命中一个相关片段。
- 11 个片段合计保存 2,355 秒；4 段抽样共 2,400 秒，折合 **约 58.9 分钟持久化/小时**。
- F6 两个“关键词不相关”的片段经人工查看仍在讲曲面参数化（ASR 把“曲面/参数化”识别成其他词），所以 81.8% 是关键词口径的**下限**，不是人工语义精度。
- F6 的 6 个片段中有 2 个分数只有 0.25/0.27，接近 L2 阈值；说明阈值附近仍有噪声。

## 结论

**能命中主题，但还不能称为“精确”。** 关注问题集确实能把片段带到正确的课堂主题；问题在于：

1. 300 秒回溯窗太大，4 个 10 分钟抽样保存了近 40 分钟音频；
2. 关键词口径受 ASR 数学术语错误影响，F6 的 precision 被低估，但也说明不能靠关键词自证；
3. 抽样点不是人工标注的“考点出现时刻”，无法测提前/滞后；
4. 4 个 case 是开发集，不是盲测；不能据此宣称全课程准确率。

## 下一步

- 对 4 个 case 人工标出考点首次出现/讲解结束的精确时间，改为时间级 precision/recall；
- 把 F6 这类低分触发（0.25–0.27）纳入阈值校准，或引入“关注问题 + 滑窗裁判”替代单文档 TF-IDF；
- 跑 full-lecture（1–2 小时）而不是 10 分钟抽样，观察误保存是否随课堂时长线性增长；
- 扩展到 12 条关注问题，至少覆盖 ODE、Green/Gauss/Stokes、重积分换元、径向调和函数；
- 用同一套问题比较“热词 L1 / 关注文档 L2 / LLM 事件裁判 L3”。

## 12 条问题的 L1/L2/L3 对比

在 12 条关注问题上各取 10 分钟片段（F10/F11 为待定/偏后位置），同一份本地转写分别跑：

- **L1 热词**：关注问题对应的关键词命中
- **L2 关注文档**：TF-IDF 相似度 ≥0.25
- **L3 LLM 裁判**：本地 4B 判断片段是否实质讲解该问题（前后半段各判一次，任一命中即 hit）

| 指标 | L1 | L2 | L3 |
|---|---:|---:|---:|
| 命中案例 | 8/12 | 9/12 | 4/12 |
| 命中率 | 66.7% | 75.0% | 33.3% |

逐例结果：

| Case | L1 | L2 score | L3 |
|---|---|---|---|
| F1 方向导数/梯度 | no | 0.408 | no |
| F2 链式法则/隐函数 | YES | 0.778 | no |
| F3 隐函数/反函数 | YES | 0.499 | no |
| F4 极值/拉格朗日 | YES | 0.447 | no |
| F5 重积分换元 | no | 0.000 | no |
| F6 第一型曲面积分 | YES | 0.916 | YES |
| F7 第二型曲线/曲面积分 | YES | 0.756 | YES |
| F8 Green/Gauss/Stokes | no | 0.000 | no |
| F9 级数/收敛 | YES | 0.700 | YES |
| F10 ODE | no | 0.000 | no |
| F11 径向调和 | YES | 0.447 | YES |
| F12 参数化/对称 | YES | 0.694 | no |

**怎么读这个表：**

- L1/L2 命中率高，不代表更准。F2 片段确实在讲“复合微分/偏导”，但 L3 判为 no；F1 片段在讲课程历史，L2 却因问题词相似给了 0.408。L1/L2 的关键词/TF-IDF 容易把“提到相关词”当成“在讲这个考点”。
- L3 更保守：只认定义、定理、推导、例题或明确解释；但它被 ASR 数学术语错误拖累，F2/F4 这类实际讲了偏导/正定的片段也被判 no。L3 的 33.3% 不是真值，只是“严格裁判 + 本地 4B + 10 分钟截断”的结果。
- 12 个片段是**按主题选出的开发样本**，不是随机负例；没有人工逐字时间标签，不能算 precision/recall。F10 的 ODE 在现有录音里没有明确对应课堂，命中 no 是数据问题，不是方法结论。

**当前判断：** L1/L2/L3 都还不能单独承担“精确命中”的验收。L2 适合当召回入口，L3 适合当保守闸门，但需要人工标注的考点时间与更可靠的数学术语 ASR 才能定量。

## 修正后的转写窗口命中（2026-10-22）

针对“整段 TF-IDF/L3 只看整段”的问题，新增 `meetingvar.lecture.find_focus`：

- 把转写切成 90–120 秒窗口，步长 45–60 秒；
- 用关注词先做候选召回，最多 5 个窗口 + 首尾窗口；
- 每个候选窗口单独交给 LLM 判断“是否在实质讲解/回答该问题”，允许同义表达、例子、推导；
- 返回带 `start/end`、证据 turn id、命中理由的片段；
- 两个以上关注词同时出现的窗口，即使小模型判 no，也保留为证据窗口（宁多保留，交给人复核）。

对同一批 12 个 10 分钟转写重跑，**9/12 命中，且都有时间戳**：

| Case | 命中片段（秒） | 说明 |
|---|---|---|
| F1 | — | 抽样段是课程历史，未出现方向导数/梯度 |
| F2 | 0–120, 180–300 | 复合微分/偏导；窗口判定“链式法则、隐函数偏导” |
| F3 | 0–120 | 隐函数/反函数定理 |
| F4 | 0–120 | 二元极值/条件极值 |
| F5 | — | 抽样段未出现重积分换元/雅可比 |
| F6 | 0–120, 480–660 | 第一型曲面积分/参数化/面积微元 |
| F7 | 0–420 | 第二型曲线/曲面积分与定向 |
| F8 | 0–120 | Green/Gauss/Stokes 应用 |
| F9 | 0–240 | 正项级数/幂级数/收敛 |
| F10 | — | 现有录音没有明确 ODE 对应课次 |
| F11 | 0–240 | 径向对称/拉普拉斯方程 |
| F12 | 0–300, 480–600 | 参数化/对称性 |

这里“0–120”是 10 分钟抽样内的相对时间，不是整堂课的绝对时间；因为抽样的起点本身是人工按主题选的，仍然不是盲测。

**结论修正：** 通过转写不是完全不能命中；把整段匹配改成“小窗口召回 + 语义裁判”后，主题级命中从 L3 的 4/12 提升到 9/12，并返回可回跳的时间段。剩下的 3 个 miss 主要是**抽样段本身没有该内容**（F1/F5）或**课程数据缺失**（F10），不是裁判漏判。下一步是把抽样换成整堂转写，并人工标注考点秒级时间，才能算 precision/recall。

## 复现

```bash
python scripts/test5_focus_pilot.py --cases cases.json \
  --json focus_report.json --md focus_report.md
```

`cases.json` 含本机视频路径和关注文档目录，不进入仓库；关注问题文本在 `benchmarks/meeting_evidence/test5_focus_questions.json`。
