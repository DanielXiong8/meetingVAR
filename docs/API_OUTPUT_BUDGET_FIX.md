# 外部 API 输出截断修复

## 现象

全库理解在某一分块（截图为第3块）报：

```text
模型输出达到上限，截断结果未采用
```

此时 API 已连通，鉴权、地址和模型名均可用，问题在输出预算，不是“模型无输出”或网络错误。

## 已复现根因

当前配置为 `api.deepseek.com` / `deepseek-flash`。使用合成项目分块实测：

| 设置 | 结果 | 输出 token | 其中思考 token |
|---|---|---:|---:|
| 4096，默认思考 | `finish_reason=length`，无正文 | 4096 | 2489 |
| 8192，默认思考 | 仍截断 | 8192 | 3333 |
| 4096，`thinking=disabled` | 完整 JSON | 1691 | 0 |

`deepseek-flash` 的隐式思考也计入 `max_tokens`。项目阅读提示原本要求列出全部人名、关键词和事件，长块可能在思考后没有足够 token 写完 JSON，因此被正确判为截断，但用户侧看起来像“API 坏了”。

## 修复

1. **限制单块输出规模**：项目阅读提示限制最多8个人名、12个关键词、6个事件，按重要性排序，禁止推理过程和额外字段；提示版本升至 `reading-v3`，旧缓存不会误用。
2. **提高外部读取预算**：桌面默认读取输出预算从4096提高到8192；本地模型仍按上下文自动封顶，不盲目提高。
3. **自动识别思考耗尽预算**：`chat_result()` 检测到 `finish_reason=length` 且 `reasoning_tokens>0` 时，自动用 `thinking=disabled` 和更大的输出预算重试一次。若提供商不支持该字段，保留原始截断错误，不伪造成功。
4. **保留真实错误分类**：仍区分鉴权、模型不存在、限流、额度、网络、空正文、截断、JSON错误及上下文预算；不因重试隐藏失败。
5. 当前本机配置已备份并改为 `llm_thinking=disabled`、`llm_reading_max_tokens=8192`，仅影响该自定义API配置。

## 验证

- 合成80条实体块：即使4096且默认思考，在输出上限约束下成功返回完整JSON（8人/12词/6事件）；更复杂的块会触发自动重试。
- 真实API多分块合成项目：5/5块完成，覆盖率100%，约12.6秒；使用 `thinking=disabled`，读取预算8192。
- 新增单元测试：模拟第一次 `length` + reasoning tokens、第二次成功，断言只重试一次、关闭思考且提高预算。
- LLM客户端/项目读取/桌面服务相关48项测试通过。

## 边界

这是外部API输出预算与思考模式的修复，不是对识别准确率或任意模型行为的保证。若其他提供商不支持 `thinking` 字段，自动重试可能失败并保留截断状态；若单块仍超出预算，应减少分块字符或提高上下文预算。真实项目重跑仍需用户自行发起，且内容会发送到配置的API。
