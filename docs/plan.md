## 1. 产品定位

**三条定位声明（对外话术，也是设计红线）**：

1. **系统级、平台无关**：依附于"项目"本身，不依附于任何一个会议软件。腾讯会议、飞书、微信视频、线下会议室，都只是声音来源。
2. **选择性取证，而非全量记录**：默认什么都不落盘，只保存与你相关的时刻。隐私和存储都因此可控。
3. **端侧优先**：音频、画面、判断全部在本机完成，数据不出电脑。离线可用。

**产品形态（MVP）**：Windows 桌面常驻应用 = 托盘 + 悬浮状态条（显示"REC for you"与已捕获片段数）。不做浏览器插件、不做会议软件内嵌。

## 2. 问题陈述

通用 AI 纪要（腾讯元宝纪要、飞书妙记、通义听悟、钉钉听记）的本质是**全场统一总结**——对全场一视同仁，必然平滑、无侧重。三个真实场景：

- **场景 A（组会 · 漏信息）**：师兄师姐汇报与你课题无关，你半听半翘；PI 突然说"某同学的某个思路/某篇论文可能对你有影响"——这句话在通用纪要里大概率一笔带过甚至丢失。
- **场景 B（例会 · 听不懂）**：面对进度质询你一一应承；会后复盘发现细节没记清，且项目对 AI 是一张白纸，专业术语转写错误甚至不知所云。
- **场景 C（培训 · 密度低）**：你薄弱的知识点纪要里没有侧重；回放音视频太长、有效信息密度太低；主办方还可能不开回放。

**共同根因：「记什么」这个决定，不该由一个通用模型替你做。**

## 3. 目标用户（对齐比赛"一个具体用户、一类真实场景、一个核心问题"）

- **场景定义**：**会议场景族**——线上组会、项目例会、评审会、培训课、访谈，同属"会议"这一类真实场景，共用同一个核心问题（通用纪要无侧重、无记忆、无溯源），**产品一套通吃**。
- **目标用户**：有持续项目记忆的知识工作者——研究生（组会/文献讨论）、项目工程师（例会/评审）、咨询/法务（条款初筛）、参加培训的学员。
- **对评委的讲法**：一类真实场景 = 会议场景族；一个核心问题 = 通用纪要无侧重；具体用户在演示中落地——**演示主线用研究生组会**（我们自己就是用户、术语问题最尖锐、选择性听讲最普遍），例会/培训用剧本数据作辅线，证明场景族通吃。
- **衔接叙事**（PPT 扩展，不实现）：差旅办公、共享工位（联想 Magic Bay 硬件生态）。

## 4. 核心概念：足球 VAR 映射

| 足球 | meetingVAR |
|---|---|
| 场上主裁（快、连续、会漏） | **草稿层**：常驻增量转写（含说话人标签）+ 滚动音频缓冲 + 低帧率录屏缓冲，均不落盘 |
| VAR 触发（疑似犯规 / 主裁主动要回看） | **兴趣命中**：热词规则 / 系统一模型打分 / 手动热键 |
| 回看室（慢、细、有完整上下文） | **系统二深读**：LLM 带项目记忆精读命中片段 |
| 回放裁决 | **厚纪要**：命中片段逐字稿（按说话人）+ 屏幕录像/关键帧 + 行动项 |
| 赛后技术报告 | **薄纪要**：全场概要（草稿层低成本生成） |
| 裁判报告归档 | **引用溯源**：每条结论带时间戳，可回听回看 |

> 【核心见解 D1 · 已采纳】**触发的是"保留"，不是"开始录"。**
> 足球 VAR 回看的是"已经发生的回合"。如果命中关键词才开始录音，丢掉的恰恰是命中**前**那两分钟——场景 A 里 PI 说"这篇论文对你有影响"之前的铺垫讨论。所以草稿层必须常驻：滚动环形缓冲保留最近约 10 分钟音频/录屏/草稿转写，命中时把缓冲转正。这一设计同时解决：意外发言不漏、默认零落盘（隐私）、存储爆炸（场景 C），而且忠实于 VAR 隐喻。

## 5. 功能规格（会前 / 会中 / 会后）

### F1 会前 · 兴趣注入
- 用户输入一句话大方向（"这周关心 XX 方法和测序污染"）；
- **项目记忆接入**：读取本地项目文件夹 / agent 记忆文件（codex 类工具）/ 指定目录，RAG 建立项目状态认知；
- 产出两样东西：**监听词表** + **兴趣向量画像**；词表同时注入 ASR 热词增强（直接解决场景 B 的术语错——hotword boosting 是现成技术）；
- 可选：读今日日历/行程（"今天有评审"→ 提高相关词权重）。一期可降级为手动勾选。

### F2 会中 · 草稿层 + 三层监听
**草稿层（常驻、不落盘）**：滚动音频环形缓冲（≈10 分钟）+ 低帧率录屏缓冲 + 增量草稿转写，**转写带说话人标签**。
【D7 讨论结论：说话人分离保留为 MVP 必做】"谁说的"是组会刚需——PI 插话那句必须归到 PI 名下，场景 A 的取证才有意义。本地 diarization 技术成熟（CAM++ / pyannote），不构成延期风险。

**三层监听**（D3 · 已采纳，每层独立可用、可消融）：
- **L1 热词规则层**：零成本、可解释、永远在线的兜底；
- **L2 系统一决策层**（Jev 模式的位置）：对转写滑窗持续做类型化打分（相关/不相关 + 概率），高频廉价。**实现用开源平替 Laya 或本地蒸馏小分类器，Jev API 只作云端增强选项**——比赛主打离线，不能依赖上线仅 12 天的云服务；
- **L3 人工 VAR 热键**：足球里主裁也有权主动要求回看。会议中一键标记当前时刻。既是漏检兜底，也是 demo 可靠性兜底。

**命中动作**：滚动缓冲转正（音频段 + 说话人标注的转写 + 低帧率录屏段）+ 关键帧截图 → 进入"待审片段池"。
【D6 讨论结论：保留录屏】录屏常驻为**低帧率（1–2 fps）内存环形缓冲**，与音频缓冲同构、同样不落盘，命中时转正片段。录屏对象是你自己的屏幕，**主动权在用户手里**：默认开启、设置里可一键关闭。低帧率 + 内存态 + 命中才写盘，存储与隐私同时可控。

**会中界面**：常驻可见的"REC for you"指示（隐私要求），悬浮条显示已捕获片段数。

### F3 会后 · 有厚有薄的纪要
- **薄纪要**：全场概要 + 议题分章，从草稿转写直接生成，成本≈0；
- **厚纪要（VAR 报告）**：每个命中片段 = 触发原因（哪个词 / 为什么打分高）+ 前后各数分钟完整上下文逐字稿（**按说话人标注**："PI 在 14:32 说……"）+ 屏幕录像片段与关键帧 + LLM 深读结论 + 建议行动项；
- **引用溯源**：每条结论带时间戳，点击回听/回看（对应本赛道参考方向"引用可溯源"）；
- 每个环节明确标注：真实实现 / 模拟 / 人工辅助（比赛硬性要求，见 §8）。

### F4 会后 · 进化（评价闭环）
- 用户快速评价：对每个命中片段点"有用/没用"，对漏掉的时刻手动补标；
- 系统一层的输出天然是类型化判断，**评价结果直接变成校准样本**（这正是用 Jev 模式的额外红利）→ 更新词表权重与打分阈值；
- 演示叙事：第一场会监听一般 → 评价 → 第二场会明显变准（"进化性"可视化）。

### F5 记忆（长期闭环）
- 会议结论回写项目记忆："上周会议决定了什么"成为下一次会前的先验——越用越懂你，也让术语表自动跟着项目走。

## 6. 竞品与差异化

| 阵营 | 代表 | 它做什么 | 它不做 | meetingVAR 的差异 |
|---|---|---|---|---|
| 全量记录派 | Limitless（已被 Meta 收购）、Plaud、Windows Recall、Teams/Zoom 内置 Copilot 纪要 | 记一切 + 统一总结 + 后检索 | 不做"选择性保存"；存储与隐私负担全在用户 | 默认零落盘，只留命中片段 |
| 平台内置派 | 腾讯元宝纪要、飞书妙记、钉钉听记 | 深度绑定自家会议，模板化总结 | 跨平台不可能；个性化≈自选模板 | 操作系统级、平台无关、兴趣驱动 |
| 关键词追踪派 | Fireflies Topic Trackers + Soundbites | 预设话题，事后统计提及、剪片段 | 事后标记而非事中取证；纯音频；无屏幕；无项目记忆；不管命中前语境 | 事中多模态取证 + 项目记忆驱动触发 |
| 学术 | 个性化 highlight detection（PR-Net 等） | 全在视频领域 | 会议场景基本空白 | 可讲"会议个性化取证的开垦者" |

**答辩预设问题**："你和 Fireflies 的 Topic Tracker 有什么区别？"——标准答案：它是**事后**在全文里贴标签，你是**事中**在系统层做多模态取证，且触发器来自项目记忆而非手工词表，命中前的上下文也保得住。

## 7. 技术架构（MVP，全端侧）

```
[任意会议平台的声音] ──► Windows 系统音频环回（WASAPI loopback, pyaudiowpatch）
        │
        ▼
   ┌────────────── 草稿层（常驻、不落盘）──────────────┐
   │ 滚动环形缓冲 ≈10min 音频 + 低帧率(1–2fps)录屏缓冲    │
   │ 增量草稿转写（FunASR/SenseVoice，热词增强）          │
   │ + 说话人分离（CAM++，本地）                        │
   └───────────────┬─────────────────────────────────┘
                    ▼
  L1 热词规则 ──► L2 系统一打分 ──► 命中 ──► 转正：音频段+录屏段+关键帧(mss)
                   ▲                                   │
  L3 手动 VAR 热键 ┘                                   ▼
                                            [待审片段池]
                                                  │
                                                  ▼
            会后：系统二 LLM 深读（带项目记忆 RAG）──► 厚纪要 / 薄纪要 / 行动项
                                                  │
            评价反馈 ──► 词表权重与阈值更新 ──► 回写项目记忆
```

技术选型：Python；pyaudiowpatch（系统音频环回）；FunASR/SenseVoice 或 faster-whisper（本地 ASR + 热词）；**说话人分离：CAM++（FunASR 生态，本地）或 pyannote.audio**；录屏：dxcam（Desktop Duplication，低帧率高效）或 mss；系统一层 = 本地小分类器 / Laya / Jev API（可选）；系统二层 = 可本地部署的 LLM；项目记忆 = 文件夹 RAG。

**真实 / 模拟边界（比赛硬性要求，诚实标注）**：
- 真实实现：音频环回采集、本地 ASR、**说话人分离（本地）**、热词命中、环形缓冲转正、低帧率录屏与关键帧截图、厚薄纪要生成、评价更新权重；
- 一期模拟/简化：系统一层先用规则代替（后期换模型）、SSH 远程记忆读取（一期只读本地文件夹）、日历读取（一期手动勾选）。

## 10. 风险与应对

| 风险 | 应对 |
|---|---|
| 隐私合规（未经同意录会议是职场红线） | 默认不落盘 + 常驻可见 "REC for you" 指示 + 只存命中片段 + 演示用自组会议并口头征得同意；录屏对象是自己屏幕、开关在用户手里 |
| 录屏存储膨胀 | 低帧率（1–2fps）内存环形缓冲 + 命中才写盘 + 转正片段压缩；存储对比数字实测进 PPT |
| 平台 ToS（如微信通话的系统级采集） | 话术只说"操作系统级、平台无关"，不宣传"绕过平台限制"；技术上 WASAPI 对所有平台等价 |
| 漏检（代词化、同义改述："你师弟刚那个"） | L2 语义打分补 L1 词表 + L3 手动热键 + 会后补标进化 |
| ASR 术语错（场景 B） | 项目记忆 → ASR 热词增强；实测纠错数字进 PPT |
| 说话人分离在嘈杂/重叠发言下出错 | 展示时用干净的模拟会议；重叠段在厚纪要标注置信度，作为"未完成项"诚实披露 |
| Jev 成熟度（上线 12 天的云服务） | L1 规则永远兜底；系统一层可本地化；Jev 仅云端增强 |
| 答辩质疑"与 Fireflies 区别" | §6 标准答案 |
| "PI 那句话不含任何关键词" | 滚动缓冲保上下文 + 语义层打分 + 手动热键，三道保险 |

## 11. 演示策略与量化指标

- **演示剧本**：主线 = 模拟组会录像（同学念稿），刻意埋两处考点——"命中关键词前两分钟有上下文"桥段、PI 插话一句（考说话人归因）；辅线 = 例会与培训片段（剧本数据，证明"会议场景族通吃"）。现场展示：命中 → 自动转正（音频 + 录屏）→ 厚薄纪要对比 → 时间戳回听。
- **进化演示**：第一场会评价 → 权重更新 → 第二场会命中变准。
- **三个量化数字（呼应"使用前后改善"）**，**全部实测填入，不许拍脑袋**：
  - 存储占用：全量录屏回放 vs meetingVAR 片段（示例占位：____ GB vs ____ MB，演示前实测）；
