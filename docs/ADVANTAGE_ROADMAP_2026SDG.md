# meetingVAR 优势拓展路线（2026 SDG Hack16）

## 0. 一句话战略

**不跟别人比“谁更会做任务/纪要”，只比“谁能证明会议里发生过什么”。**

核心资产不是“又一个 Agent”，而是：

```text
选择性取证  +  证据链  +  项目记忆/时序图谱  +  本地优先
```

这四个东西组合起来，才是别人短期抄不走的。

## 1. 先把优势拆成五层

| 层 | 现在有什么 | 还可以往哪拓 |
|---|---|---|
| 捕获 | 双源音频、屏幕帧、实时转写、手动 VAR、三层触发 | 全局热键/语音“标记这一刻”、会前关注驱动、跨平台采集 |
| 定位 | 转写搜索、RAG、find_focus、时间戳 | “找回那 30 秒”：自然语言 + 人/时间/类型过滤 + 屏幕帧 |
| 证据 | turn/quote/引用校验、片段 WAV/屏幕 | 一键证据包、SHA256、manifest、链式保管 |
| 记忆 | FactStore、RAG、时序知识图谱 | 承诺账本、决定变更对比、跨会议冲突 |
| 本地 | 本地 ASR、本地模型、离线回退 | AI PC NPU/GPU、Magic Bay 麦克风/摄像头、加密与权限 |

## 2. 三个签名功能（只做这三个就够打）

### 签名 1：Evidence Pack（一键证据包）

**为什么是它**：评委听完“证据 Agent”是抽象的；一份可以带走的证据包是具体的。

选中一个片段/一次问答，导出一个 ZIP：

```text
evidence_2026-10-26_1430/
  manifest.json        # 会议、时间、说话人、turn_ids、quote、哈希
  summary.pdf          # 一页结论 + 引用
  transcript.txt       # 相关转写窗口
  audio.wav            # 命中前后音频
  screen_*.png         # 关键屏幕帧
  SHA256SUMS.txt       # 所有文件哈希
```

manifest 里写：

```json
{
  "session_id": "go_xxx",
  "window": {"start": 1430.2, "end": 1492.8},
  "citations": [{"turn_id": "turn_242", "quote": "..."}],
  "files": [{"path": "audio.wav", "sha256": "..."}],
  "generated_by": "meetingVAR 0.16.0",
  "consent": "local-capture"
}
```

**一句话卖点**：

> “这不是会议纪要，这是一份可以交给老板/客户/合规的证据包。”

**技术落点**：复用 `data/clips`、`SessionCatalog`、FactStore/RAG 引用、`hashlib`；新增 `evidence_pack.py` + UI 导出按钮。

### 签名 2：Commitment Ledger（承诺账本）

把“谁在什么时候承诺了什么、后来谁改了口”做成一个列表，而不是让用户自己翻会议。

视图：

```text
承诺：周五交付第一版
负责人：小林
首次承诺：2026-03-11 第 2 节 00:14:32
当前状态：已被替代
变更：2026-03-18 第 1 节 00:08:10 改为周一
证据：[原句] [回放]
```

底层直接用现有 FactStore + KG 的 `valid_from/valid_to/supersedes`，不需要新造数据。

**一句话卖点**：

> “普通纪要只会写‘交付时间调整’，我们告诉你谁改的、什么时候改的、原话是什么。”

### 签名 3：Find the 30 Seconds（找回那 30 秒）

一个搜索框，输入：

> “PI 上次提到的那篇可能影响我课题的论文”

返回：

- 命中的 30–90 秒片段；
- 说话人、时间戳、屏幕帧；
- 原句；
- 为什么命中（关键词/语义/项目记忆）；
- 一键跳转/导出。

底层复用 `find_focus` + RAG + KG；重点不是再做一个搜索，而是**把“定位精度”做到秒级**。

## 3. 三条拓展线，不要同时铺

### 线 A：证据深度（最优先）

- Evidence Pack
- 屏幕帧与转写对齐
- 哈希/链式保管
- 引用校验
- 同意提示/录制指示

目标：**“可信”成为产品名。**

### 线 B：时间与关系（第二优先）

- Commitment Ledger
- 决定变更对比
- 跨会议冲突
- 项目/人物/风险子图

目标：**“跨会议记忆”成为留存理由。**

### 线 C：AI PC / 硬件（第三优先）

- 本地 NPU/GPU 调度
- 离线模式（断网演示）
- Magic Bay 麦克风/摄像头增强
- 电量/温度感知的捕获策略

目标：**联想 AI PC 的差异化场景。**

## 4. 和对手的合作姿态

不要什么都自己做：

| 对手 | 关系 |
|---|---|
| 豚秘（消息→任务） | 把 meetingVAR 的承诺/行动项导出给豚秘，做“证据→任务” |
| 元枢（系统级分身） | 不抢系统权限；做它最缺的“可信证据层” |
| 沃曼（A2A 协作） | 把证据包作为 A2A 的可验证消息附件 |
| LensSlide（演示） | 把证据片段嵌入演示，做“有出处的汇报” |

一句话：

> 别人做“执行”，我们做“证据”；执行层可以接我们。

## 5. 技术路线（对应现有代码）

| 能力 | 现有模块 | 下一步 |
|---|---|---|
| 片段/转写 | `pipeline.py`、`data/clips`、`SessionCatalog` | 证据包导出 |
| 事实/承诺 | `agent/memory.py` | Commitment Ledger 视图 |
| 跨会议变化 | `kg/store.py` 时序边 | 变更对比 API/UI |
| 精确检索 | `rag.py`、`lecture.py` | 秒级定位 + 屏幕帧 |
| Agent 回答 | `agent/loop.py` | 引用 node/edge/document |
| 本地模型 | `llm.py`、FunASR | 离线模式/模型回退 |
| 知识图谱 | `kg/*` | 6–10 节点演示图、冲突审核 |

## 6. 评测指标（用来证明“证据”不是口号）

- **Time to Evidence**：从提问到定位到片段 < 10 秒；
- **Evidence Precision**：返回片段中真正相关的比例；
- **Citation Support**：回答引用能在原文中找到的比例；
- **False Capture Minutes/Hour**：每小时误保存时长；
- **Storage Saved**：相对全量录屏节省的存储；
- **Evidence Pack Verify**：SHA256 全部通过；
- **Offline Pass**：断网后仍能转写/检索/导出。

这些指标比“准确率 95%”更能说服评委。

## 7. 72 小时冲刺顺序

### Day 1

1. Evidence Pack 后端 + UI 导出；
2. 用真实片段生成一份可打开的 ZIP/PDF；
3. 确认 SHA256 校验通过。

### Day 2

1. Commitment Ledger 列表 + 变更对比；
2. 用两场会议造一个“周五→周一”的 demo；
3. 做 3 分钟录屏 fallback。

### Day 3

1. Find the 30 Seconds 搜索框 + 时间戳跳转；
2. 准备 3 个 demo 场景；
3. 按 3 分钟脚本排练 5 遍，删掉所有讲不清的功能。

## 8. 明确不做

- 不做通用任务管理/日程（豚秘更强）；
- 不做系统级数字分身（元枢叙事更大，但风险高）；
- 不做全量录屏（违背隐私和存储优势）；
- 不做另一个会议纪要 App；
- 不在路演里讲模型名/参数，讲问题和证据。

## 9. 最终一句话

**把 meetingVAR 从“能总结会议的 Agent”变成“能出具会议证据的系统”。**  
证据包是抓手，承诺账本是留存，秒级定位是体验，本地 AI PC 是壁垒。
